# task-decompose

**Языки:** [English](README.md) | Русский

Разбивает нетривиальный запрос на упорядоченный атомарный чек-лист с проверяемыми условиями «готово, когда». Используйте до планирования, проектирования архитектуры или написания кода для всего, что выходит за рамки одного тривиального изменения.

- **Имя:** `task-decompose`
- **Версия:** `1.1.0`
- **Лицензия:** MIT
- **Совместимость:** `opencode`

## Обзор

`task-decompose` превращает неоднозначный или многошаговый запрос в конкретный план выполнения. На выходе получается чек-лист небольших, упорядоченных и независимо проверяемых подзадач. У каждой подзадачи есть явное условие завершения, поэтому прогресс можно проверять без догадок.

Этот навык предназначен для использования **до реализации**, а не во время или после неё. Если запрос нельзя свести к одному тривиальному изменению, сначала выполните декомпозицию.

## Когда использовать

Используйте этот навык, когда запрос:

- сложнее одного тривиального изменения;
- достаточно неоднозначен, чтобы порядок реализации имел значение;
- вероятно, потребует планирования, архитектуры или нескольких изменений кода;
- состоит из зависимых шагов, неизвестных или граничных случаев;
- достаточно крупный, чтобы был возможен выход за рамки первоначального объёма.

## Когда не использовать

Не используйте этот навык для:

- одного тривиального изменения;
- запроса, который уже полностью декомпозирован и проверен;
- чисто информационных вопросов, не требующих плана реализации.

## Протокол

1. **Сформулируйте цель одним плотным предложением.**
2. **Определите:**
   - входы;
   - выходы;
   - ограничения;
   - неизвестные;
   - граничные случаи.
3. **Создайте атомарные подзадачи.** Каждая подзадача должна быть:
   - по возможности независимой;
   - правильно упорядоченной;
   - проверяемой.
4. **Выведите план строго в таком формате:**

## PLAN
- [ ] 1. <подзадача> — готово, когда: <условие>
- [ ] 2. <подзадача> — готово, когда: <условие>

5. **Выполняйте по порядку.** Отмечайте задачу как `[x]` только после прохождения самопроверки.
6. **Остановитесь и выполните декомпозицию заново**, если выход за рамки объёма превышает 20% или появляются новые неизвестные.

## Формат вывода

План должен использовать строго такую структуру:

## PLAN
- [ ] 1. <подзадача> — готово, когда: <условие>
- [ ] 2. <подзадача> — готово, когда: <условие>
- [ ] 3. <подзадача> — готово, когда: <условие>

Каждое условие «готово, когда» должно быть объективно проверяемым.

## Правила

- Держите **не более 7 подзадач на уровень**. Если их больше, сгруппируйте в этапы.
- **Никогда не реализуйте до создания чек-листа.**
- Сохраняйте и обновляйте существующий чек-лист. Не создавайте его заново.
- После завершения тела сразу выводите `PLAN`.
- Никогда не вызывайте этот навык повторно.
- Никогда не перенаправляйте.

## Пример

Запрос: «Добавить валидацию запроса и тесты для эндпоинта создания пользователя».

## PLAN
- [ ] 1. Изучить текущий эндпоинт создания пользователя и его тесты — готово, когда: поведение эндпоинта, пробелы в валидации и существующее покрытие тестами задокументированы.
- [ ] 2. Определить правила валидации для обязательных полей и невалидного ввода — готово, когда: для каждого правила есть явный ожидаемый ответ с ошибкой.
- [ ] 3. Реализовать валидацию в эндпоинте — готово, когда: невалидные запросы возвращают задокументированные ошибки, а валидные запросы по-прежнему успешны.
- [ ] 4. Добавить тесты для валидных, невалидных и граничных входных данных — готово, когда: все новые тесты проходят и покрывают каждое правило валидации.
- [ ] 5. Запустить соответствующий набор тестов и провести самопроверку чек-листа — готово, когда: тесты проходят и каждый пункт чек-листа проверен.


## Критерии качества

Корректная декомпозиция должна удовлетворять всем условиям:

- цель выражена одним предложением;
- ограничения, неизвестные и граничные случаи видны;
- у каждой подзадачи есть проверяемое условие «готово, когда»;
- подзадачи упорядочены и атомарны;
- реализация не начинается до создания чек-листа;
- выход за рамки объёма обнаруживается и обрабатывается остановкой и повторной декомпозицией.
